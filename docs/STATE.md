## Connectivity: four layers, and who gets to say what

| Edge kind | owner | meaning |
| --- | --- | --- |
| `net` | the file | two pins listed under one `SIGNAL` |
| `same_component_shared_net` | the file | one component's own pads listed under that `SIGNAL` |
| `inferred_crossing_from_name_rules` | the server's name rule | a reading of SHAPE/DEVICE words |
| `inferred_crossing_asserted_by_caller` | the model | the model's own conclusion, echoed verbatim |

A reading of a name is not knowledge about the part. `:func:`tools.evaluate_crossing`` is the
question surface — it states the file facts, the structure (geometry, footprint, name tokens), a
verdict, and a ready-to-pass record — and adds no crossing itself. When the model agrees with the
question it passes that record in `assumed_bridges`, and the crossing comes back labelled as the
model's conclusion. The model's assertion takes precedence over the name rule: exactly one edge per
proposed pair, with the suppressed rule hint still visible as `also_rule_offered`.

The server never claims a part is continuous. `bridge_eligibility` answers two factual questions —
does the name classify it passive, and does it have exactly two pads carrying nets — and states the
shape caveat (`shape_unreliable` for `RSENSE_VIRTUAL_04_SMD_2512`, whose declared shape is the
virtual placeholder itself) without recommending either direction.

## Behaviour changes since the first wiring pass

- `_bfs_paths` (graph.py ~466) had a `continue` that treated the first target reached as the end of
  the search, so a route whose second target sat behind a first (`J15 -> RS1 -> L45 -> ... -> U7`)
  disappeared when both were requested. Fixed: record the found target, still expand the node; stop
  expanding only when every requested target has a route.
- `pad_pairs_by_distance` in the `:func:`tools._structure`` block sorts
  `(not across_footprint, distance)` so in/out candidates survive `pad_pair_limit` truncation, and
  `pads_already_sharing_a_net` (the file's own joins inside one component) is surfaced next to it.
- `find_connected_components` now takes `net=` as a start (fan-out from a net), `exclude_components`
  / `exclude_nets` skip parts and rails in a traversal, and `find_shared_rails` echoes its
  `exclude_nets`/`exclude_components` so a filtered result proves what was filtered.
- `paths_between` (graph.py) takes `max_fanout`/`max_size` so the chassis rail (`GND`, 2858
  members) cannot explode the search, and every traversal answers the same `exclude_nets` question
  (`get_net` now also lists `similar_components`, the components sharing most of a net).
- Net membership pagination is mandatory everywhere: net sizes run 1–2858.
